设计原则

两条铁律：① 规范先行，美化在后 —— 任何页面先符合本规范再谈好看；② 品牌一致，两端分治 —— 同一品牌橙，Web 端克制使用，移动端可氛围化使用。
1
克制优先（Web 端）

后台是效率工具：中性底色 + 白卡片 + 细边框，橙色仅用于主按钮、选中态、链接、关键数字，占比 < 10%。

2
亲和氛围（移动端）

小程序是 C 端工具：允许橙金渐变（Hero、金额、主操作）、玻璃质感与轻动效，占比可达 30%~40%。

3
同一品牌 token

两端共享同一套色板 / 字号 / 间距 / 圆角基准，差异只体现在「应用强度」与「组件形态」。

2

色彩规范

品牌橙为核心主色，中性色承载 90% 界面，功能色表达状态。所有取色必须从下方色板取值，禁止硬编码其它色值。

橙色使用规则（关键）

W
Web 端 · 克制

橙 = 功能主色：主按钮 / 菜单选中 / 链接 / 分页当前页 / 1~2 个关键指标。禁止：大面积渐变底、玻璃光斑、金橙发光文字。

M
移动端 · 氛围

橙 = 品牌氛围：Hero 渐变、余额/金额渐变发光、主操作、选中态。允许金橙辉光（#FFC53D 系列），但表单/列表主体保持中性。

9

动效原则

动效服务于状态反馈，不抢内容。Web 快而轻（150–300ms），移动端稍缓（200–400ms）。统一缓动 ease-out。
W
Web 端

hover 150ms / 展开 200ms / 弹窗 300ms。仅用位移+透明度，禁旋转、弹跳。

M
移动端

入场 400ms fade-up、数字滚动 800ms easeOutCubic、按钮按压缩放 0.96。

K
关键帧统一

Web 端全局 keyframes 名统一 sxwl- 前缀；移动端统一放 uni.scss + 复用。

表单规范

后台最高频组件。Web：标签左对齐、必填红 * 前置、错误红字提示；移动端：标签置于控件上方，一行一字段。

Web 布局

弹窗表单一行 2 列（12 栅格），搜索表单一行 3~4 列；标签固定宽 100px 左对齐，必填红 * 前置。

M
移动端布局

标签在控件上方（垂直表单），一行一字段；校验失败红字提示 + 输入框红边。

E
错误态

提交时错误提示出现在对应字段下方（12px 红字）；错误解除即消失；不拦截整体提交后的全局反馈。

15

页面模板

组件拼成页面的标准结构。所有 CRUD 页遵循「列表页」模板（由 SxwlPage 提供），表单遵循「弹窗表单」，登录遵循「登录页」模板。

① 列表页（标准 CRUD · Web）

页头：标题 + 描述 + 主操作（新增 = 橙）

② 弹窗表单 / ③ 登录页

F
弹窗表单

宽 416，一行 2 列；标题 + 分隔线 + 底部「取消 / 确定（橙）」；由 SxwlFormModal 提供。

L
登录页

居中卡片：Logo（橙）+ 平台名 + 副标题 + 表单 + 底部版权；橙色只在 Logo 与登录按钮。
