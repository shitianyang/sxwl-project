## 4️⃣ 文件管理 — RustFS 分片上传（SysFileController）

### ✅ 后端架构验证

| 层级 | 文件 | 状态 | 说明 |
|------|------|------|------|
| Controller | SysFileController.java | ✅ | `/rustfs/file`，10 个 API |
| Service | SysFileService.java | ✅ | 文件业务接口 |
| ServiceImpl | SysFileServiceImpl.java | ✅ | 分片上传 + MD5 秒传 |
| Util | S3Presigner.java | ✅ | AWS SDK V4 签名生成 |

**设计说明**：RustFS 基于 **对象存储（MinIO/Ceph）** 实现，采用 S3 协议，无需传统 ORM 的 Mapper/XML 层。文件元数据存储在内表（`rustfs_file_info`），通过 MyBatis-Plus 直接操作。

**API 端点清单**：

| # | 功能 | 路径 | 方法 | 说明 |
|---|------|------|------|------|
| 1 | 初始化上传 | `/rustfs/file/upload/init` | POST | 生成分片 ID |
| 2 | 上传分片 | `/rustfs/file/upload/chunk` | POST | 上传单个分片 |
| 3 | 完成上传 | `/rustfs/file/upload/complete` | POST | 合并分片 |
| 4 | MD5 秒传 | `/rustfs/file/upload/md5/check` | GET | 检测已上传 |
| 5 | 查询已上传分片 | `/rustfs/file/upload/chunks` | GET | 断点续传支持 |
| 6 | 下载文件 | `/rustfs/file/download/{id}` | GET/POST | 流式下载 |
| 7 | 获取预签名 URL | `/rustfs/file/presigned-url/{id}` | GET | 临时访问链接 |
| 8 | 分页查询文件列表 | `/rustfs/file/page` | GET | 文件元数据分页 |
| 9 | 删除文件 | `/rustfs/file/{id}` | DELETE | 软删除 |
| 10 | 简单上传 | `/rustfs/file/simple-upload` | POST | <5MB 文件直传 |

---

### ✅ 前端 SxwlUpload 组件验证

| 层级 | 文件 | 状态 | 说明 |
|------|------|------|------|
| Hook | hooks/useChunkedUpload.ts | ✅ | 分片上传逻辑封装 |
| Component | components/SxwlUpload/index.tsx | ✅ | 通用上传组件 |
| Page | File/index.tsx | ✅ | 文件管理列表页 |

**核心功能**：
- ✅ 分片上传：默认分片大小 5MB，并发数 3
- ✅ MD5 秒传：FileSliceReader + SparkMD5 计算文件哈希
- ✅ 断点续传：checkMd5() + getUploadedChunks() 检测已上传分片
- ✅ 进度展示：整体进度条 + 分片上传进度
- ✅ 大文件支持：默认 2GB 限制，可配置
- ✅ 重试机制：失败自动重试 3 次
- ✅ 文件预览：图片类型支持缩略图预览

**上传流程**：
```
用户选择文件（>5MB）
  ↓
调用 useChunkedUpload Hook
  ↓
计算 MD5（FileSliceReader 切片读取 + SparkMD5）
  ↓
调用 initUpload() → 获取分片 ID
  ↓
并发上传分片（concurrency: 3）
  ├─ chunk1: POST /rustfs/file/upload/chunk
  ├─ chunk2: POST /rustfs/file/upload/chunk
  └─ chunkN: POST /rustfs/file/upload/chunk
  ↓
所有分片上传完成 → 调用 completeUpload()
  ↓
后端调用 MinIO CompleteMultipartUpload
  ↓
返回文件元数据 → 刷新文件列表
```

**潜在问题**：✅ **无明显问题**（无 XML 层符合 S3 协议设计）
